# Code guide: Smile Community Centre theme

A short map so anyone can find their way around. Read `AGENTS.md` and `HANDOVER.md` for the working rules.

## Where things live (`wp-content/themes/smile-community-child/`)

| Folder / file | What it does |
| --- | --- |
| `functions.php` | Loads everything below. Holds the theme version (`SMILE_THEME_VERSION`). |
| `inc/setup.php` | Theme supports, menus, self-hosted fonts, Elementor asset trimming. |
| `inc/security.php` | All security hardening, in numbered sections. Every rule can be switched off with a filter. |
| `inc/performance.php` | Speed: banner photo preload, image size limits, WebP output, trimming unused front-end files. |
| `inc/slider.php` | Home hero slider: default slides, Customize settings, and the HTML output. Only the first slide loads straight away; the rest load lazily. |
| `inc/home-sections.php`, `inc/components.php` | The `[smile_*]` sections used across the pages. |
| `inc/elementor/` | Smile widgets for Elementor (generated by `scripts/build-elementor-widgets.py`). |
| `inc/importer.php`, `demo/` | "Apply latest design": page layouts (`pages.json`), photos (`images.json`), site text (`strings.json`). |
| `template-parts/` | Built-in header and footer. |
| `assets/css/` | Source CSS. Edit these, never the files in `assets/build/`. |
| `assets/js/main.js` | All front-end JavaScript (menu, sticky header, slider, WhatsApp chat, forms). |
| `assets/build/` | Minified files the site actually loads. |
| `assets/images/` | Logo kit (`brand/`), bundled photos (`photos/`), slider photos (`slides/`). |
| `assets/fonts/` | Nunito, Figtree, Newsreader, Caveat (latin subset, WOFF2). |

Forms (contact, volunteer, partner, careers) live in the bundled plugin `wp-content/plugins/smile-community-core/includes/forms.php`.

## CSS layout

`main.css` and `home.css` are read top to bottom. The first part is the base design system; later blocks are dated releases
(for example `2.36.0 Inner pages`), each with a comment explaining what it changes and why. Newer blocks override older ones
on purpose, so add new styles at the end in a new dated block rather than editing older ones in place.

## After editing

```bash
python3 scripts/build-css.py                 # rebuild minified CSS
python3 scripts/build-elementor-widgets.py   # only if section shortcodes changed
python3 scripts/extract-strings.py           # only if site text changed
cd wp-content/themes/smile-community-child && python3 ../../../scripts/check-theme.py
bash scripts/build-theme-zip.sh              # build the upload zip
```

If you change `assets/js/main.js`, update `assets/build/main.min.js` too, then bump the version in `style.css` and
`functions.php` and add a `CHANGELOG.md` entry.

## Security at a glance

- Security headers (CSP basics, HSTS on HTTPS, clickjacking and MIME-sniffing protection, a strict Permissions-Policy).
- HTTPS redirect, no WordPress version leak, XML-RPC off, author/user enumeration blocked (URL, REST, sitemap).
- Login: 5 failed attempts per 15 minutes per connection, generic error messages, strong passwords required.
- Password reset: 5 requests per hour per connection.
- No theme/plugin code editor in wp-admin, no application passwords, no pingbacks or trackbacks, no comments on pages.
- Forms: nonce, honeypot, signed minimum fill time, per-IP rate limit, all input sanitised and escaped.

Server-level settings that a theme cannot control (ask the host, or add to `wp-config.php` / `.htaccess`):
`define( 'DISALLOW_FILE_MODS', true );` on the live site, unique salts, blocking PHP execution in `wp-content/uploads`,
Brotli or gzip compression, and long browser caching for `wp-content/themes/*/assets/`.
